## Как запустить

```bash
python3 scripts/eval/fetch.py              # скачать корпуса → .cache/eval/raw/ (идемпотентно)
python3 scripts/eval/build-punct-set.py    # собрать punct.jsonl / clean.jsonl / stats.json
npm run eval:punct -- --set dev            # настраивать по dev (≈ 14 с)
npm run eval:punct -- --set test           # отчитываться по test (≈ 7 с)
npm run eval:punct -- --set dev --diff 30 --json .cache/eval/run.json   # промахи, лишние, 30 случаев на ручную оценку
npm run eval:punct -- --set dev --engine ../vychitka-prev                # те же данные на другом чекауте (до/после)
npm run eval:punct -- --set dev --exclude-domain MedSpellchecker         # без шаблонных медкарт
```

Самопроверки без данных: `python3 scripts/eval/build-punct-set.py --selftest`, `node --test test/unit/eval-punct.test.js`.

### Как строится набор

Текст делится на слова и «пробелы» между ними; у каждого пробела считается подпись из классов знаков (`,` `;` `:` `.` `…` `!` `?` тире, дефис, кавычки, скобки, прочее). Пара становится пунктуационным случаем, если слова выравниваются 1:1 и различаются только подписи/пробелы:

- **pure** — слова совпадают буквально (982 пары);
- **derived** — корпус правит и слова (орфография, регистр, ё), но число слов то же; берём слова из исправления и пунктуацию из исходника (4 650). Без этого режима из SAGE почти ничего не остаётся — там исправляют всё сразу.

Не считаются пунктуацией: различия глифов внутри класса (`-`/`—`, `"`/`«»`, `...`/`…`), дефис («кто то» → «кто-то»), прочие символы, непарные скобки-смайлики. Отбрасываются пары с латиницей, разметкой, переносами строк, короче 3 слов / 15 знаков, длиннее 80 слов / 600 знаков (всего отброшено 2 845 строк; 2 949 пар с изменением числа слов пошли только в «чистые»).

Два вида правок **вне зачёта** (движок их не делает, но они в файле и в отчёте отдельной строкой; `--with-terminal` возвращает): конечные `. ! ? …` в самом конце текста и границы предложений, вставленные перед словом, которое уже написано с заглавной (медкарты-простыни).

### Как считается

Issue движка применяется к предложению; каждый пробел, у которого изменилась подпись или пробельность, — одно «изменение». Изменение **попало**, если лежит в том же пробеле, что эталонная правка, и вставляет/убирает те же знаки (или их подмножество) либо даёт ровно эталонный пробел. Spelling/grammar-issue и глиф-только замены (`typo.dash`, `typo.quotes`) не участвуют. **Near-miss** — изменение в пробеле, который эталон тоже правит, но иначе (считается лишним, показывается отдельно). Всё даётся для `confidence:'sure'` и для `sure + check`.

## Топ-10 типов пропусков (dev, по выборке 700 промахов из 5 599)

Примеры — пересказ, не цитаты.

1. **Бессоюзное сложное и сложносочинённое с «и» при разных подлежащих** — самый большой класс: «и» 182 правки с recall 13.7 %, плюс запятые перед «я / не / это / он» (~160). *Пример:* «весь мир склонился бы перед вами и вы носили бы моё имя» — запятая перед «и» не ставится. Нужна проверка наличия второго подлежащего (местоимение / существительное в им. п. сразу после «и»).
2. **«как»** — 103 правки, 38 % и только как `check`: сравнительные обороты, «так же, как», «то время, как». `punct.comma-comparative` не даёт `sure` вовсе.
3. **Союзные слова кто / когда / где / чем / куда и «кстати»** — движок их находит (61–88 % в `check`), но ни разу не `sure`. Дешёвый выигрыш по recall-sure: повышать уверенность после глагола/существительного, как уже сделано для «что / который».
4. **Обособленные обороты после существительного** — причастный оборот («…по прожигам, периодически мелькающим в углу»), приложения и уточнения («пекла его один раз, на крестины племянника»). `punct.participle` срабатывает 28 раз на весь dev.
5. **Однородные члены без союза** — перечисления, где нет ни одной запятой («Дозоры: Дневной, Ночной, Сумеречный…»; «документы: паспорт, справка…»). Правил нет.
6. **Тире между подлежащим и сказуемым-существительным и в эллипсисе** — 951 правка с тире, recall 1–2 %: «Футбол — один из самых популярных видов спорта», «Али — один из её детей», «Москва — 10–15 тыс.». `punct.dash-subject` дал 15 срабатываний.
7. **Кавычки у названий** (ВКонтакте, фильм, газета, конкурс «Мисс…») и оформление реплик — 951 правка, 1 %. Без словаря названий недостижимо; правки «- реплика. - реплика» → кавычки считаем шумом формата.
8. **Двоеточие перед пояснением / в бессоюзном** («обратите внимание: пробиты ли отверстия») и замены двоеточие ↔ тире — 703 правки, 1 %; больше половины из медкарт.
9. **Лишняя запятая, которую надо убрать** — ~6 % промахов: после обстоятельства в начале («в очередное пробуждение, я…»), «объясняла, что, я…», перед «и» при однородных. У движка правил на удаление почти нет (`odnako-start`, `double`).
10. **Пробелы внутри кавычек и скобок** («" за "», «( он же…») и после точки в сокращениях («1 руб.15 коп.») — `space-before/after` их не трогают.

Реальные ложные срабатывания движка, которые стоит чинить (из 30 случайных «лишних» 21 — настоящие ошибки):

- `punct.comma-repeated-conj` ставит запятую при **одном** «и» между двумя однородными («овощи и фрукты», «рассчитанными и предсказанными»): 99 лишних на чистых dev, precision 47 % — главный источник шума в режиме `check`.
- `punct.intro`: «может быть» как сказуемое («может быть связано»), «естественно / таким образом / в принципе / ну конечно» — 131 лишнее на чистых; в `sure` попали «В принципе,» и «Ну, конечно».
- `punct.gerund` / `punct.participle` после «и» режут однородные причастия («оформленный и, подписанный»); `gerund` ставит запятую после первого слова главной части («Отчаявшись злой, король»).
- `punct.comma-before-conj`: при «который» в род. падеже после существительного запятая нужна перед существительным («…новых вождей, имён которых…», «…проблемы, на решение которой…»), а движок ставит перед «которых» — и это `sure`; «ещё когда», «пока» после наречия.
- `punct.speech-colon` / `speech-after` на названиях в кавычках («заявлял "Фонтанке" глава…»).

## Где эталон ненадёжен

- **MedSpellchecker** (826 пар, 15 % набора): шаблонные анамнезы. Аннотаторы то убирают двоеточие после «Наследственность», то меняют «;» на «,», добавляют скобки и точки в «простынях» без границ предложений. Классы «:», «;», «()» почти целиком оттуда; для настройки двоеточия/точки с запятой этот домен лучше исключать (`--exclude-domain MedSpellchecker`).
- **Вкусовые замены**: «, » ↔ « — », «:» ↔ « — », «;» → «,» в перечнях — считаются промахами, хотя исходник часто допустим.
- **Near-miss в `space-before`**: 65 из 67 лишних — «анамнез :» → движок убирает пробел, эталон убрал весь знак. Движок прав.
- **«Чистые» из SAGE не вполне чистые**: из 30 случайных «лишних» в 9 движок прав или спорно — пропущенные в эталоне запятые перед «какое», перед причастным оборотом («земли, подаренной…»), перед «перед тем как», перед сравнительным «как какой-то». Реальная precision выше примерно на 5–8 п. п., а частота лишних на SAGE-части чистых завышена примерно на треть. Часть russian_gec-«чистых» тоже без запятой перед «перед тем как».
- **Конечные знаки и границы предложений** (3 234 + 1 222 правок) — вынесены из зачёта; без этого recall падал бы на треть за счёт не-задачи движка.
- russian_gec пунктуационных случаев почти не содержит — его роль только «чистые» простые предложения (лишних 6–10 / 1000).
