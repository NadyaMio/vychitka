# Движок «Вычитки» — спецификация

Движок проверки русского текста без ИИ: словари + правила. Чистый Node.js (CommonJS), без нативных модулей, работает в `worker_threads` внутри main-процесса Electron. Никаких сетевых вызовов.

## Расположение

```
src/engine/
  index.js         — публичный API (ниже)
  worker.js        — обёртка для worker_threads: принимает {id, method, args}, отвечает {id, result|error}
  tokenize.js      — предложения, слова, позиции
  morph.js         — загрузка Az (OpenCorpora), isKnown(word), parse(word), генерация кандидатов
  spelling.js      — орфография
  punctuation.js   — пунктуация
  grammar.js       — грамматика и согласование
  typography.js    — типографика
  repeats.js       — повторы слов рядом
  literary.js      — литературная правка (стиль)
  wordinfo.js      — карточка слова
  compare.js       — сверка двух версий
bases/             — ВСЕ данные, которые обновляются отдельно от приложения
  manifest.json    — { "version": "2026.10.1", "date": "2026-10-21", "files": [{ "path": "az/words.dawg", "sha256": "...", "size": 123 }, ...], "modules": [...] }
  az/              — словари Az (скопировать из node_modules/az/dicts)
  freq/ru_50k.txt  — частотный список (hermitdave/FrequencyWords, CC BY-SA 4.0) для ранжирования подсказок
  extra/words.txt  — свой список частых слов, которых нет в OpenCorpora (референс, онбординг, дедлайн, лонгрид, спецпроект, промокод, …) — ~300+ слов
  rules/*.json     — данные правил: вводные слова, подчинительные союзы, канцелярит/штампы, слова-усилители, фразовые орфографические замены и т.п.
scripts/build-bases-manifest.js — пересчитывает sha256/size всех файлов bases/ и пишет manifest.json (версию берёт из аргумента или увеличивает patch)
test/engine/*.test.js — node:test (`node --test test/engine`)
```

`az` уже стоит в node_modules. Можно ставить другие npm-зависимости только на чистом JS и только со свободными лицензиями (MIT/BSD/Apache/ISC). Данные — только со свободной лицензией; лицензии и атрибуцию записать в `bases/LICENSES.md`.

## Модель документа

```js
doc = { paragraphs: [ { text: string, kind: 'h' | 'p' } ] }
```
Позиции — индексы UTF-16 в `paragraphs[i].text`. В тексте могут быть ` ` (неразрывный пробел) — считать его пробелом при разборе.

## API (`src/engine/index.js`)

```js
await init({ basesDir, userWords = [] })      // грузит Az из basesDir/az и данные; повторный вызов = перезагрузка (после обновления баз)
setUserWords(words: string[])                  // «Мой словарь»: эти слова (в любой форме регистра) не считать ошибками
basesInfo() -> { version, date, modules: [{ id, title, detail, version, status }] }   // для экрана «Словари и базы»
check(doc, settings) -> { issues: Issue[], stats: { chars, words, paragraphs, ms } }
literary(doc, settings) -> { score: number /*0..10, 1 знак*/, scoreAfter: number, metrics: Metric[], issues: Issue[] }
wordInfo(word, { para, start, end, doc }) -> WordInfo
compare(aDoc, bDoc, { appliedFixes = [] }) -> CompareResult
```

### settings (с дефолтами «Редакционная норма»)
```js
{
  checks: { spelling: true, punctuation: true, grammar: true, typography: true, repeats: true },
  yo: 'meaning',         // 'meaning' — не трогать е/ё, кроме слов из списка, где ё меняет смысл (всё/все не трогать!); 'always' — ставить ё везде, где словарь знает ё-форму; 'never' — заменять ё на е
  quotes: 'elochki',     // «» снаружи, „“ внутри
  dash: 'em',            // « — » между словами: длинное тире с пробелами (перед тире — неразрывный)
  numbers: true,         // 150000 → 150 000 (неразрывный пробел) для чисел ≥ 10000; годы (1000–2100 рядом со словами «год/г.» или четыре цифры) не трогать
  uncertain: 'mark',     // 'mark' — спорное отдавать с confidence:'check'; 'skip' — спорное не выдавать
  skipQuotes: true       // не проверять пунктуацию внутри «…» и прямой речи
}
```

### Issue
```js
{
  id: string,                 // стабильный для одинакового входа: `${ruleId}:${para}:${start}`
  para: number, start: number, end: number,   // заменяемый фрагмент [start,end)
  category: 'spelling'|'punctuation'|'grammar'|'typography'|'style'|'repeat',
  ruleId: string,             // напр. 'spell.unknown', 'spell.chtoby', 'punct.comma-before-conj', 'typo.dash'
  before: string,             // то, что сейчас в тексте (= text.slice(start,end))
  after: string,              // основной вариант замены
  alternatives: [{ text: string, note: string }],   // доп. варианты (для spelling — другие слова с пометкой формы, напр. 'дат. п.')
  confidence: 'sure'|'check', // 'check' = «Проверьте»
  why: string,                // объяснение по-русски, 1–2 предложения, как в макете
  source: string              // «Правила орфографии и пунктуации, 2006 · союзы», «Орфографический словарь (OpenCorpora)», «Профиль: редакционная норма» …
}
```
Для пунктуации-вставки запятой фрагмент берётся «слово + пробел + слово» (`before: 'решили что'`, `after: 'решили, что'`) — так карточка читается как в макете. Issues не пересекаются: при конфликте приоритет spelling > grammar > punctuation > typography > repeat. Сортировка: по para, затем start.

## Правила (минимум, обязательно)

**Орфография (`spelling`)**
- Слово (кириллица, допускается дефис) неизвестно, если у Az нет разбора с `parser === 'Dictionary'`, его нет в extra/words.txt, и нет в userWords. Слова с заглавной буквы НЕ в начале предложения считать именами собственными и не помечать. Аббревиатуры (все заглавные), слова с цифрами/латиницей — пропускать.
- Кандидаты: свой генератор правок на расстоянии 1 (удаление, вставка, замена, перестановка соседних; алфавит а-яё и дефис), оставить только известные словарю. Если пусто — расстояние 2, но только через типовые ошибки (н/нн, тся/ться, ь/ъ, удвоенные согласные, безударные о/а, е/и, пропущенная буква). Ранжирование: типовая ошибка выше; частотность из freq; совпадение грамматических тегов с исходным словом (Az parse с typos или по окончанию). `note` у альтернатив: краткая форма по-русски: «вин. п., мн. ч.», «дат. п.», «им. п.».
- confidence 'sure', если лучший кандидат — типовая ошибка (н/нн, тся/ться, ь) или единственный кандидат; иначе 'check'. Если кандидатов нет — issue с after = before? Нет: не выдавать issue без замены; вместо этого `ruleId:'spell.unknown-nosugg'`, after = before, confidence 'check', why «Слова нет в словаре. Проверьте написание или добавьте в «Мой словарь»».
- Фразовые правила (rules/phrases.json): «что бы» → «чтобы» (если после «что бы» нет запятой и следующее слово — инфинитив или «не»+инфинитив или глагол прош. вр.; иначе не трогать: «что бы ни случилось»), «до поздна»→«допоздна», «не смотря на»→«несмотря на» (без «в глаза/на часы» и т.п.), «в течении (+ вр. существительное: недели, года, дня, часа, месяца, времени, этого…)»→«в течение» — это grammar, «в следствии»→«вследствие», «на подобии»→«наподобие», «в виду (+ того что)»→«ввиду», «в место»→«вместо», «из за»→«из-за», «из под»→«из-под», «по моему» в начале — пунктуация (вводное), «вообщем»→«в общем», «как-будто»→«как будто», «тоесть»→«то есть», «впринципе»→«в принципе», «врядли»→«вряд ли», «итак»/«и так» — не трогать. Сохранять регистр первой буквы.

**Пунктуация (`punctuation`)**
- Запятая перед подчинительными союзами и союзными словами в середине предложения: что, чтобы, если, когда, потому что, так как, хотя, пока, который (все формы), где, куда, откуда, будто, как будто, словно, поскольку, несмотря на то что, после того как, прежде чем, ли (косвенный вопрос — 'check'). Не ставить, если: слово стоит в начале предложения; перед ним уже знак препинания; перед ним сочинительный союз (и, или, а, но) или другой подчинительный союз; «что» — местоимение в вопросе/ «не то что», «что-то»; составной союз разрывается («потому что» → запятая перед «потому»); «чтобы» после «для того» / «с тем» — запятая перед «для»… (упростить: перед «для того чтобы» → перед «для»); сравнительный оборот «как» — не трогать вовсе. confidence 'sure' для что/чтобы/если/который после глагола или существительного; иначе 'check'.
- Запятая перед противительными «а», «но», «однако», «зато» в середине предложения (если нет). 'sure' для «но», «а»; 'check' для «однако».
- Вводные слова (rules/intro.json: конечно, безусловно, во-первых…, например, кстати, по-моему, наверное, вероятно, кажется, разумеется, итак, значит?, словом, впрочем, к сожалению, к счастью, в частности, по сути, кроме того, с одной стороны, с другой стороны, таким образом, в общем, в итоге…) — обособить с обеих сторон, учитывая начало/конец предложения. «Однако» в начале предложения + запятая — 'check'. «Значит», «кажется», «наверное» — 'check'.
- Оборот с «несмотря на» в начале предложения: запятая после оборота перед подлежащим/сказуемым — 'check' (граница: ищем первое слово после «несмотря на X Y», которое местоимение/существительное им. п. или глагол; если не уверены — не выдавать).
- Обращение в начале предложения (имя собственное + «,» нет) — пропустить, не делать.
- Двойные знаки: «,,», « ,» (пробел перед запятой/точкой), отсутствие пробела после запятой/точки перед буквой — 'sure' (это typography или punctuation, на выбор, но одно).

**Грамматика (`grammar`)**
- «в течении» + время → «в течение»; «в продолжении» + время → «в продолжение»; «в заключении» в значении «в конце» → «в заключение» ('check').
- Предлог «по» + «приезде/прибытии/окончании/завершении» — правильно; «по приезду/прибытию/окончанию/завершению» → «по приезде/прибытии/окончании/завершении» ('sure').
- «согласно/благодаря/вопреки» + родительный падеж → дательный (через Az: если следующее существительное только в gent и есть datv-форма — предложить её) ('check').
- «оплатить за» → «оплатить» ('sure'), «одеть пальто/куртку…» (на себя) → «надеть» ('check').
- Согласование прилагательного с существительным в соседней паре (прил.+сущ.) по роду/числу/падежу, если Az однозначен и расхождение явно — 'check'. Можно ограничиться только однозначными случаями.

**Типографика (`typography`)**
- Дефис/короткое тире между словами с пробелами (« - », « – ») → « — » (перед тире неразрывный пробел: `after` = ' —'? Нет: в `after` возвращать «—», а неразрывный пробел перед тире добавлять в соседнем символе — сделать фрагмент «пробел+дефис» → « —»). Карточка: before '-', after '—'. Выбрать удобную реализацию, главное — итоговый текст после применения правильный.
- Прямые кавычки "…" → «…» (вложенные → „…“). Карточка: before '"референсы"', after '«референсы»'.
- Числа ≥ 10000 без разделителей → разряды через   (before '150000', after '150 000'). Не трогать телефоны, годы, номера с ведущим нулём, числа в датах.
- Двойные пробелы, пробел перед знаками препинания, «...» → «…», «(c)»→«©» не надо.
- Буква ё по настройке yo.
- Неразрывные пробелы после коротких предлогов/союзов НЕ выдавать как issues (их ставит экспорт); дать отдельную функцию `applyNbsp(text) -> text` в typography.js, экспортировать из index.js.

**Повторы (`repeat`)**
- Одна и та же лемма (Az normalize, кроме служебных частей речи и местоимений, длина ≥ 4) 2+ раза в пределах 3 предложений → issue на втором вхождении, after = before, alternatives пустые, confidence 'check', why «Слово «X» повторяется рядом (N раза в 3 предложениях)». ruleId 'repeat.near'.

**Литературная правка (`literary`)** — категория 'style' (и 'repeat' для повторов)
- Канцелярит и штампы по шаблонам из rules/kanc.json (регэкспы по словоформам + варианты замены): «в рамках данного/этого X» → «в X»/убрать; «осуществить/осуществлять + отглагольное сущ.» → глагол (осуществить проведение → провести; осуществляем сбор → собираем; осуществить контроль → проконтролировать …, словарь пар сущ.→глагол в rules/nominal-verbs.json, ≥ 60 пар); «было принято решение (+инф.)» → «решили»; «X является Y» → «X — Y» / убрать связку ('check'); «данный/данные» → «этот/эти»; «что в свою очередь является ключевым фактором» и подобные штампы (≥ 80 шаблонов: «играет важную роль», «на сегодняшний день», «в настоящее время», «имеет место быть», «в целях», «с целью», «в связи с тем что», «по причине того что», «в случае если», «на данный момент», «является неотъемлемой частью», «широкий спектр», «ключевой фактор»…).
- Отглагольное + пассив: «командой было принято решение осуществить проведение» → альтернативы «мы решили провести», «команда решила провести» (особый составной шаблон: «[кем] было принято решение» + инфинитив; ищите подлежащее-творительный перед ним).
- Слова-усилители и паразиты (rules/intensifiers.json: очень, безусловно, абсолютно, крайне, действительно, конечно же, просто, буквально, реально, фактически, в принципе…) → after '' (удалить) с аккуратной обработкой пробелов/запятых; confidence 'check'.
- Длинное предложение: > 30 слов или > 3 придаточных (по запятым+союзам) → issue на всё предложение, ruleId 'style.long', after = before, why «N слов, M придаточных — разделите на 2–3 предложения», confidence 'check'.
- Пассив (краткое причастие + «был/была/было/были» или «-ся» глагол в страдательном значении, по Az: PRTS) → 'check'.
- Повторы: те же, что repeat.near, плюс одинаковые сочетания из 2 слов в одном предложении («позволяет нам … позволяет нам») → alternatives с перефразом нет, просто сигнал.
- metrics: `[{ id:'kanc', title:'Канцелярит и штампы', count }, { id:'long', title:'Длинные предложения', count }, { id:'repeat', title:'Повторы рядом', count }, { id:'passive', title:'Пассив и отглагольные', count }, { id:'intens', title:'Слова-усилители', count }]`.
- score: 10 минус штрафы на 1000 знаков (канцелярит 0.6, длинное 0.8, повтор 0.4, пассив 0.4, усилитель 0.3), не ниже 0, округлить до 0.1. scoreAfter — оценка, если применить все issues (пересчитать на исправленном тексте).

**Карточка слова (`wordInfo`)**
```js
{ word, known: bool, lemma: string|null, posTitle: 'прилагательное', tags: 'вин. п., мн. ч.', 
  suggestions: [{ word, note: 'вин. п., мн. ч.', fits: bool /*подходит по контексту*/ }],   // до 5
  rule: string|null,     // напр. «В прилагательных с суффиксом -енн- пишутся две «н».» — для типовых ошибок
  forms: string|null,    // краткая сводка форм лексемы, напр. «ответственный; кр. ф. ответствен, ответственна» (из Az: inflect)
  morph: [{ form, tags }],   // для вкладки «Морфология»: 6–12 основных форм
  dal: null              // словарь Даля пока не встроен
}
```

**Сверка (`compare`)**
- Выравнивание абзацев (LCS по нормализованным абзацам с порогом похожести), затем пословный diff внутри пары (можно npm `diff`, MIT, уже установлен).
- Нормализация для сравнения: схлопнуть пробельные, ` `≡пробел только для признака «слетел пробел»; перенос «слово-\nслово» в B склеивать как «словослово» и сравнивать.
- Типы расхождений: `lost` (абзац есть в A, нет в B), `added` (наоборот), `notApplied` (в B стоит `before` одной из appliedFixes, а в A — её `after`), `space` (различие только в пробелах/неразрывных пробелах), `changed` (иначе), `format` — не делать в движке.
- CompareResult: `{ pairs: [{ a: index|null, b: index|null }], diffs: [{ id, type, title /*«Потерян абзац» …*/, aPara, bPara, aRange:[s,e]|null, bRange:[s,e]|null, text /*объяснение как в макете*/ }], similarity: 0..100 (целое, по словам), words: n }`.

## Золотой тест (обязательный)

Текст из макета (абзацы):
1. «Вчера вечером мы собрались в небольшом кафе на Покровке что бы обсудить план нового проекта. Как и ожидалось, разговор затянулся до поздна: каждый хотел высказатся, но мало кто слушал других.»
2. «В конце концов Анна предложила простое решение - разбить задачу на этапы и назначить ответственых. Не смотря на усталость все согласились.»
3. «Мы решили что первый этап займёт две недели. В течении этого времени нужно собрать "референсы" и подготовить черновик - без него двигаться дальше бессмысленно.»
4. «Отдельно обсудили бюджет. Анна считает что на первый этап хватит 150000 рублей, если не заказывать внешний дизайн.»

Ожидаемые issues (все обязательны, лишних — не больше 2):
- P1: punct «Покровке что» → «Покровке, что» (или «Покровке что бы» → «Покровке, чтобы» — допустимо объединить с орфографией, но тогда одна карточка spelling «что бы»→«чтобы» + одна punct); spelling «что бы»→«чтобы»; spelling «до поздна»→«допоздна»; spelling «высказатся»→«высказаться» (sure).
- P2: typography «-»→«—»; spelling «ответственых»→«ответственных» (sure; alternatives включают «ответственным», «ответственные»); spelling «Не смотря»→«Несмотря»; punctuation «усталость все»→«усталость, все» (check).
- P3: punctuation «решили что»→«решили, что» (sure); grammar «В течении»→«В течение»; typography '"референсы"'→'«референсы»'; typography «-»→«—». «референсы» НЕ ошибка.
- P4: punctuation «считает что»→«считает, что»; typography «150000»→«150 000».
- После применения всех after текст должен совпасть с исправленным эталоном (тире с неразрывным пробелом перед ним).

Литературный эталон:
«В рамках данного проекта командой было принято решение осуществить проведение серии встреч с читателями. Данные встречи являются важным инструментом, который позволяет нам получать обратную связь, а также позволяет нам лучше понимать потребности читателей, их интересы и ожидания, что в свою очередь является ключевым фактором для дальнейшего развития проекта.» / «На каждой встрече мы рассказываем о новых книгах и осуществляем сбор вопросов. Ожидается: «в рамках данного проекта» (kanc), «командой было принято решение осуществить проведение» с альтернативами «мы решили провести»/«команда решила провести», «Данные встречи являются» (kanc, check), «позволяет нам» повтор, «что в свою очередь является ключевым фактором» (штамп → «что важно»), «осуществляем сбор» → «собираем», «безусловно» и «очень» (усилители), третье предложение — long. score в диапазоне 4–7.

Сверка: A = исправленный эталон, B = тот же текст, где: абзац 3 удалён; «ответственных» → «ответственых»; «150 000» → «150000»; «дизайн» → «дизайн-\nер». appliedFixes содержит фикс «ответственых→ответственных». Ожидается: lost(абзац 3), notApplied(ответственых), space(150000), changed(дизайн-ер).
