# Движок «Вычитки»: как устроен и как добавить правило

Спецификация — `docs/ENGINE_SPEC.md`. Здесь — практическая карта кода и данных.

## Где что лежит

```
src/engine/
  index.js        публичный API, загрузка баз, сборка результата check()/literary()
  worker.js       обёртка для worker_threads ({id, method, args} → {id, result|error})
  context.js      контекст абзаца: токены, предложения, кавычки/прямая речь, поиск соседних слов
  tokenize.js     токенизатор и деление на предложения
  morph.js        Az.js (OpenCorpora): isKnown, parse, lemma, кандидаты правок, описания тегов
  rules1956.js    Правила 1956 г.: rule(n), search(), source(ref)
  spelling.js     фразовые правила (rules/phrases.json) + неизвестные слова
  punctuation.js  запятые перед союзами (rules/conj.json), вводные слова (rules/intro.json), «несмотря на», «Однако,», механика знаков
  grammar.js      в течение / по приезде / согласно + дат. п. / оплатить / одеть-надеть / согласование
  typography.js   тире, кавычки, разряды чисел, многоточие, пробелы, буква ё, applyNbsp()
  repeats.js      повторы леммы в 3 предложениях, одинаковые биграммы
  literary.js     стиль: rules/kanc.json, отглагольные (rules/nominal-verbs.json), усилители, длинные предложения, пассив, оценка
  wordinfo.js     карточка слова
  compare.js      сверка двух версий (LCS абзацев + пословный diff)
  util.js         makeIssue, resolveOverlaps, applyIssues, matchCase, wordRegex, levenshtein
bases/            все данные (см. bases/LICENSES.md); движок грузит Az ТОЛЬКО отсюда
```

## Конвейер `check(doc, settings)`

1. Для каждого абзаца строится контекст (`context.js`): токены с позициями UTF-16, предложения, спаны кавычек и прямой речи (при `skipQuotes` пунктуация внутри них не проверяется).
2. Включённые проверки (`settings.checks.*`) отдают свои issues независимо друг от друга.
3. `resolveOverlaps` убирает пересечения: приоритет spelling > grammar > punctuation > typography > repeat; при равном приоритете побеждает более длинный фрагмент. Запятая перед союзом («Покровке что»), столкнувшаяся с орфографической правкой самого союза («что бы» → «чтобы»), не выбрасывается, а урезается до «Покровке » → «Покровке, » — так обе карточки доживают до пользователя.
4. `uncertain: 'skip'` отбрасывает всё с `confidence: 'check'`.
5. Каждому issue проставляются `ref` (только существующие параграфы) и `source`: если есть `ref` — «Правила 1956 · § N · Раздел», иначе собственный источник правила («Орфографический словарь (OpenCorpora)», «Розенталь · управление», «Профиль: редакционная норма»).

`literary(doc)` работает так же, но только с правилами стиля; `style.long` (всё предложение) никогда не конфликтует с другими issues. Оценка: `10 − Σ(вес × количество) × 1000 / max(знаков, 2000)`, веса: канцелярит 0,6, длинное предложение 0,8, повтор 0,4, пассив 0,4, усилитель 0,3. Нижняя граница 2000 знаков нужна, чтобы одна правка в коротком тексте не роняла оценку на несколько баллов. `scoreAfter` — та же оценка на тексте, к которому применены все `after ≠ before`.

## Как написаны правила

### Данные (без кода)

| Файл | Что описывает | Ключевые поля |
|------|---------------|---------------|
| `rules/phrases.json` | Орфография сочетаний: «что бы» → «чтобы», «из за» → «из-за», «-нибудь», «по-русски», частые ошибки-слова | `pattern` (регэксп без границ слова, границы добавит движок), `after` (шаблон с `$1`), `cond` (имя условия из `spelling.js`), `confidence`, `why`, `ref` |
| `rules/conj.json` | Подчинительные/противительные союзы, стоп-слова перед ними, предлоги для сдвига запятой («дом, в котором») | `text`, `confidence`, `needsHead` (sure только после глагола/существительного), `skipIfPrev/skipIfNext`, `shiftPrep`, `forms`, `nextVerb`, `kind: 'li'` |
| `rules/intro.json` | Вводные слова | `text`, `confidence`, `confidenceStart`, `startOnly`, `skipIfPrev/skipIfNext`, `skipIfNextGen`, `skipIfNextCase` |
| `rules/kanc.json` | Канцелярит, штампы, плеоназмы | `pattern`, `after` (шаблон: `$1`, `{1:loct}` — склонить группу 1, `{1:short}` — краткая форма, `{map:1}` — подстановка по `map`, `{neg}`, `{cut:…}`; пустая строка — удалить; нет поля — сигнал без замены), `alternatives`, `cond`, `why` |
| `rules/nominal-verbs.json` | Пары «отглагольное существительное → глагол» и глаголы-связки | `verbs` (сов. → несов.), `generic`, `pairs[{noun, perf, impf, with}]` |
| `rules/intensifiers.json` | Усилители и слова-паразиты (удаляются) | `text`, `skipIfPrev/skipIfNext`, `skipIfNextPunct`, `skipIfNextPos`, `startOnly` |
| `rules/yo.json` | Пары, где «ё» меняет смысл (режим `yo: 'meaning'`) | `e`, `yo`, `note` |
| `rules/grammar.json` | Списки для грамматики: временные существительные, «по приезде», одежда, формы «оплатить/одеть» | — |
| `rules/passive.json` | Глаголы на «-ся», которые обычно означают пассив | `reflexivePassive` |
| `extra/words.txt` | Слова, которых нет в OpenCorpora; принимаются и их падежные формы (основа + типичное окончание) | по слову в строке |

Все регэкспы в данных пишутся без `\b` (он не работает с кириллицей) — движок оборачивает их в `(?<![\p{L}\p{N}-])(?:…)(?![\p{L}\p{N}-])` с флагами `giu`. Регистр первой буквы замены берётся из текста (`matchCase`).

### Код

Условия, которые нельзя выразить регэкспом, живут рядом с данными: `CONDS` в `spelling.js` (например, `chtoby` — дальше инфинитив или глагол прошедшего времени), `KANC_CONDS` в `literary.js`. Неизвестное имя условия один раз пишется в `console.warn`, правило при этом применяется.

Проверки, которым нужна морфология целиком (согласование, «является» → тире, «осуществляем сбор вопросов» → «собираем вопросы», «командой было принято решение» → «мы решили»), написаны в JS и опираются на `morph.dictParses()` и `parse.inflect()` из Az.

## Как добавить новое правило

**Фразовая орфография** — строка в `rules/phrases.json`:

```json
{ "id": "spell.adverb-merge", "pattern": "в двоём", "after": "вдвоём", "confidence": "sure", "ref": [83],
  "why": "Наречие «вдвоём» пишется слитно." }
```

Нужно условие — добавьте функцию в `CONDS` (`spelling.js`) и укажите её имя в `cond`. `ref` — только номера параграфов из `bases/reference/rules-1956.json`, проверенные по тексту (`node -e "console.log(require('./src/engine').rule(83))"` после `init`, либо `searchRules('наречия слитно')`).

**Штамп** — строка в `rules/kanc.json`:

```json
{ "id": "kanc.obrazom", "pattern": "коренным образом", "after": "в корне",
  "why": "«Коренным образом» — штамп: «в корне», «полностью»." }
```

**Вводное слово** — строка в `rules/intro.json`; если слово бывает и наречием, добавьте `skipIfPrev`/`skipIfNext` и ставьте `confidence: "check"`.

**Новая проверка с кодом** — функция в соответствующем модуле, которая получает `ctx` и возвращает issues через `makeIssue({ para, start, end, category, ruleId, before, after, confidence, why, ref, source })`. Обязательно: `before === text.slice(start, end)`; для вставки запятой фрагмент — «слово + пробел + слово». Затем тест в `test/engine/units.test.js` и прогон `test/engine/false-positives.test.js`.

После правки данных: `node scripts/build-bases-manifest.js 2026.10.2` и `npm run test:engine`.

## API (`src/engine/index.js`)

```js
await init({ basesDir, userWords })   // повторный вызов — перезагрузка баз
setUserWords(words)
basesInfo()                           // { version, date, modules: [{ id, title, detail, version, status, bytes?, toggle? }] }
check(doc, settings)                  // { issues, stats: { chars, words, paragraphs, ms } }
literary(doc, settings)               // { score, scoreAfter, metrics, issues }
wordInfo(word, { para, start, end, doc })
compare(aDoc, bDoc, { appliedFixes })
rule(n)                               // параграф Правил 1956 г. или null
searchRules(query, limit = 20)        // [{ n, section, group, url, snippet, score }]
applyNbsp(text)                       // неразрывные пробелы для экспорта
applyIssues(doc, issues)              // применить after ≠ before, вернуть новый doc
defaultSettings()
```

`Issue` дополнительно к спецификации содержит `ref: number[]` (параграфы 1956 г.), `note` (грамматическая помета к `after` у орфографии) и `metric` (у стиля: kanc / long / repeat / passive / intens).

Запуск в `worker_threads`: `new Worker(require.resolve('src/engine/worker.js'))`, сообщения `{ id, method, args }` → `{ id, result }` или `{ id, error: { name, message, stack } }`. Разрешённые методы — `worker.METHODS`.

## Что работает ненадёжно

- Запятые ставятся по спискам союзов и стоп-слов, без синтаксического разбора. Всё, что не «что/чтобы/если/который после глагола или существительного», отдаётся как `check`. Сравнительные обороты с «как» не трогаем вовсе (§ 150).
- Вводные слова, совпадающие с наречиями («кстати», «возможно», «действительно», «значит», «кажется»), — `check`; часть из них проверяется только в начале предложения.
- «В итоге», «в конце концов», «наконец», «правда» намеренно не считаются вводными (Розенталь), хотя ТЗ их упоминает.
- Согласование прилагательного с существительным проверяется только для однозначных расхождений в числе и роде; падежные — нет (слишком много омонимии).
- «Согласно/благодаря + родительный» срабатывает только если у существительного нет других прочтений, кроме родительного.
- Орфография: слово с заглавной буквы не в начале предложения считается именем собственным и не проверяется; в начале предложения неизвестное имя даст `check`. Кандидаты — расстояние 1 (и 2 через типовые ошибки): при трёх и более ошибках в слове подсказки не будет (`spell.unknown-nosugg`).
- Режим `yo: 'always'` ставит «ё» только там, где словарь не знает е-варианта (поэтому «все/всё» не трогается).
- Стилистические замены (`literary`) — всегда `check`; «осуществляем сбор вопросов» → «собираем вопросы» склоняет дополнение, но дальние зависимые слова («серии встреч» → «серию встреч») остаются как есть.
